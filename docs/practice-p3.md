# P3 · Воспроизводимый конвейер «данные → результат → сайт»

## Реализация

Расчёт написан на стандартной библиотеке Python: `csv`, `Counter`, `hashlib`, `json`, `datetime`.
Для исходного футбольного среза не нужны pandas или Jupyter на раннере.
MkDocs и все его транзитивные зависимости закреплены точными версиями в `requirements.txt`;
версия Python — в `.python-version`.

```bash
python -m pip install -r requirements.txt
make experiment  # CSV -> JSON, CSV, Markdown, HTML figure
make test        # модульные тесты + независимый пересчёт
make build       # повторный experiment, строгая сборка, проверка локальных ссылок
```

`Makefile` гарантирует вызов расчёта до сборки сайта, а не полагается на устаревшую картинку.
`verify_results.py` пересчитывает числители отдельными фильтрами, не вызывая основную функцию агрегации.
Проверяется также равенство чисел в спецификации графика и в таблице.

## Кэш

Ключ SHA-256 включает байты `data/matches.csv`, исполняемый `scripts/experiment.py`, `requirements.txt`, `data/manifest.json`
и версию Python. Изменение данных или кода не может использовать прежний кэш случайно. При изменении CSV нужно явно обновить `dataset_version` и `subset_sha256` в manifest: несовпадение хеша прерывает сборку.
`render_chart.py` выполняется после чтения кэша: правки представления не требуют повторного расчёта, но попадают в HTML.

Кэш `.cache/experiment/<key>.json` содержит только результат вычислений.
Дата сборки, коммит и режим HIT/MISS пишутся заново при каждом вызове, чтобы HIT не показывал старую версию сайта.
GitHub Actions дополнительно кэширует pip и каталог результатов. Кэш не является архивом научной публикации:
он может быть удалён, и сборка обязана корректно выполнить MISS.

[Численные замеры MISS/HIT и полных сборок](generated/measurements.md).
Это небольшой расчёт; ускорение не следует переносить на обучение моделей или считать выигрышем всего CI.

## Проверка изменения исходных данных

```bash
python scripts/demo_update.py
```

Скрипт создаёт временную копию проекта, меняет один результат матча с не-победы Home на победу Home,
явно обновляет версию и хеш в manifest, выполняет три запуска и проверяет:

1. Исходный запуск — MISS.
2. После изменения CSV — MISS, новый SHA-256, ровно на одну победу Home больше.
3. Повтор без изменений — HIT.
4. Изменился HTML графика, а не только таблица.

Запись результата — `evidence/update-demo.json`.
Это **локальный функциональный тест**, а не доказательство уже выполненного push и обновления удалённого сайта.
Исходный пользовательский CSV не изменяется. Искусственно изменённый матч не используется как научный результат.

### Обязательная удалённая демонстрация после включения Pages

1. Зафиксировать исходный URL, SHA-256 из JSON и скриншот графика.
2. В отдельной демонстрационной ветке изменить копию набора; отметить её `dataset_version` как `demo`.
3. Создать PR: получить успешные lint/build без публикации.
4. После осознанного merge в main дождаться deploy и healthcheck.
5. Сопоставить commit и SHA-256 на опубликованной странице с репозиторием.
6. Сохранить ссылки на запуски и скриншот нового значения, затем вернуть подлинные данные отдельным коммитом.

Не выдавать тестовый счёт за реальный матч. Если менять фактические данные нельзя,
можно исправить подтверждённую ошибку либо расширить заранее объявленный срез; описание и версия набора должны измениться вместе с данными.

## Метаданные

На [странице результатов](generated/results.md) отображаются коммит, время UTC,
версия набора и SHA-256 данных. В JSON дополнительно есть SHA-256 расчётного кода, ключ кэша и версия Python.
В Actions используется `GITHUB_SHA`; локально без Git — `local-uncommitted`.
Для абсолютно одинаковых байтов HTML нужно отдельно фиксировать время сборки:
текущая цель — воспроизводимость чисел и трассируемость, а не побайтовая идентичность страниц с разными датами.

## Подтверждения и оставшиеся проверки

- Изменение именно CSV → push → новое значение на опубликованном графике: локальный тест выполнен, но удалённая демонстрация изменения данных ещё не проведена.
- Доставка на отечественный хостинг: нужны аккаунт, путь, проверенный SSH host key и отдельный deploy-ключ.
- Работа на GitHub-hosted runner подтверждена [успешным lint/build/deploy](https://github.com/danyaborisoff-collab/python/actions/runs/40208648142). Локальные замеры не выдаются за замеры этого runner.
- Лицензия исходного футбольного набора: необходимо уточнить первоисточник.

## Вывод

Для этого расчёта исполнение в CI проще, чем отдельное хранилище готовых результатов.
При росте данных или появлении GPU-задач вычисления переносятся наружу,
а текущий CSV/JSON-интерфейс публикации сохраняется с дополнительным manifest запуска.
