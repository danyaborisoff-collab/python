# Отладка и контроль качества

Раздел разделяет **фактическую инфраструктурную ошибку** и **намеренные негативные тесты**.
Последние действительно выполняются и сохраняют stderr, но не выдаются за случайные ошибки разработки.

## 1. Нет права записи в GitHub

**Текст:** `403 Resource not accessible by personal access token` при POST `/git/refs`.

- **Гипотеза:** публичность дала чтение, но подключение не имеет Contents:write.
- **Проверка:** README доступен, создание новой ветки отклонено API.
- **Решение:** выдать подключению права Contents и Workflows на выбранный репозиторий либо загрузить архив вручную. Раскрытый в чате токен отозвать, не использовать повторно.
- **Статус:** устранено повторным защищённым подключением GitHub: новое подключение успешно создало ветку `research-site-t2-p3`. Прежнее подключение продолжало возвращать 403.

## 2. Дублирование матча

**Текст:** `ValueError: duplicate game_id=...` (точный ID — в `evidence/duplicate.log`).

- **Гипотеза:** одна запись дважды увеличивает знаменатель и число исходов.
- **Проверка:** во временном CSV добавлена копия первой строки; запуск `experiment.py --force` возвращает ненулевой exit code.
- **Решение:** не удалять молча; исправить вход по подтверждённому источнику. Исходный CSV не повреждается, тестовая копия уничтожается.
- **Статус:** намеренный отказ воспроизведён скриптом `negative_checks.py`.

## 3. Недопустимый счёт

**Текст:** `ValueError: invalid score at line 2`.

- **Гипотеза:** отрицательное число голов испортит разность голов и классификацию исхода.
- **Проверка:** в тестовой копии первый `home_club_goals` заменён на `-1`.
- **Решение:** строгая проверка целочисленного диапазона 0–30, отказ сборки вместо публикации неверной метрики.
- **Статус:** stderr и exit code сохранены в `evidence/invalid-score.log`.

## 4. Битая внутренняя ссылка

**Текст:** `Doc file 'index.md' contains a link 'missing-page.md', but the target is not found among documentation files.`

- **Гипотеза:** `--strict` должен сделать предупреждение о ссылке фатальным.
- **Проверка:** временно добавлена ссылка на отсутствующий Markdown, выполнено `mkdocs build --strict`.
- **Решение:** исправить путь/добавить целевую страницу; проверки `not_found`, `unrecognized_links`, `anchors` настроены как warnings, превращаемые strict в отказ.
- **Статус:** реальный лог и ненулевой exit code — в `evidence/strict-broken-link.log`.

Не любая проблема ссылки автоматически ловится одним флагом `--strict`: он повышает до ошибки именно предупреждения.
Поэтому также запускается `check_site.py`, проверяющий итоговые HTML, якоря и локальные ресурсы.

## Воспроизведение

```bash
make negative
python scripts/demo_update.py
make test build
```

`make negative` завершается успешно только если все три испорченных случая действительно завершились с ошибкой.
Это не имитация красного workflow GitHub: удалённый негативный запуск нужно получить отдельно после подключения записи.

## Дополнительные проверки

- Независимый пересчёт побед по исходному CSV.
- Совпадение чисел таблицы и спецификации графика.
- Проверка поиска в браузере при заблокированных внешних доменах.
- HTTP 200, контрольная строка, отсутствие внешних runtime-ресурсов.
- Проверка формулы и графика без CDN, desktop/mobile screenshot.

Результаты браузерного теста и скриншоты сохраняются в `evidence/` после его выполнения.

## 5. Ложное срабатывание проверки ссылок на 404.html

**Текст:** `404.html: root-relative URL /python/assets/...`.

- **Гипотеза:** проверка запрещает все корневые ссылки, хотя Material специально формирует их для 404, обслуживаемой на неизвестной глубине URL.
- **Проверка:** строгая MkDocs-сборка успешна; все сообщения относятся только к 404 и имеют корректный префикс site_url.
- **Решение:** разрешить только для 404 корневые пути под точным базовым путём из canonical главной страницы; проверить наличие целевых файлов. Остальные страницы по-прежнему обязаны иметь переносимые относительные ссылки.
- **Статус:** исходный лог сохранён в `evidence/site-check-initial.log`; после изменения проверка выполняется заново. Это реальная найденная ошибка валидатора, не специально испорченный CSV.

## 6. Нечитаемые символы в автономной формуле

**Наблюдение:** буквы MathML показаны квадратами вместо p, W, N.

- **Гипотеза:** стандартный italic-вариант MathML требует математических глифов, которых нет в шрифтовом наборе окружения.
- **Проверка:** формула присутствует в DOM и занимает место, но desktop screenshot показывает отсутствующие глифы. Проверки только `getBoundingClientRect()` было недостаточно.
- **Решение:** для этой простой формулы явно задан `mathvariant="normal"`, используются обычные латинские глифы без внешних шрифтов. Дробь и индексы остаются нативными MathML.
- **Статус:** исправление просмотрено на desktop и мобильных скриншотах при блокировке внешних доменов.

## 7. Скрытый запрос к GitHub API

**Текст:** `GET https://api.github.com/repos/danyaborisoff-collab/python/releases/latest → 404`.

- **Гипотеза:** стандартная ссылка на репозиторий в Material подгружает статистику stars/releases и создаёт внешнюю runtime-зависимость.
- **Проверка:** браузерный сетевой журнал фиксирует запрос, хотя график и страницы уже локальные.
- **Решение:** небольшой theme override `overrides/partials/source.html` оставляет обычную ссылку без JS-компонента статистики. Тема не форкается.
- **Статус:** итоговый `browser-qa.json` фиксирует отсутствие попыток внешних запросов и ошибок HTTP.
